# 正文嵌入：视频号、其他文章，以及各种富组件

**一句话结论**：草稿箱 API（`draft/add`）只能塞「文字 + 图片 + 链接的 HTML」。
**视频号卡片、站内文章超链接、视频、音频、小程序、位置、投票等富组件，API 都带不过去**——
`draft/add` 要么直接丢弃，要么只留个残缺属性导致编辑器里一直转圈/报错。

所以本 skill 的做法是：**在正文里产出一块「占位卡」，把标题和链接明明白白写进去，
发布进草稿箱后，由你在公众号编辑器里手动替换成真组件。**

本文说明：哪些能自动化、哪些不能、为什么、以及你在编辑器里具体怎么做。

---

## 1. 总览：什么能自动，什么要手动

| 想插入的东西 | API 能带吗 | 本 skill 怎么做 |
|-------------|-----------|----------------|
| 正文文字、标题、加粗、引用、列表 | ✅ 能 | 全自动 |
| 正文图片（`<img>`） | ✅ 能 | 自动上传到微信图床后写入 |
| 公式、表格、代码块 | ✅ 能（HTML 表达） | 全自动 |
| **指向外部网站的链接** | ⚠️ 会被过滤 | 自动转「上标脚注 + 文末参考链接」 |
| **指向微信站内文章的超链接** | ❌ 不可靠 | `:::article` 占位卡 → 手动插 |
| **视频号卡片** | ❌ 会被丢 | `:::video` 占位卡 → 手动插 |
| **往期推荐 / 合集** | ❌ 会被丢 | `:::readmore` 占位卡 → 手动插 |
| 腾讯视频 / 上传视频 | ❌ 会被丢 | 手动插 |
| 音频、小程序、位置、名片、投票 | ❌ 会被丢 | 手动插 |
| 「阅读原文」链接 | ✅ 能 | frontmatter `source_url` |

## 2. 视频号（推荐关注的重点）

### 现象
你在编辑器里插一个视频号卡片，能看到视频的封面、时长、播放键。
但**通过 `draft/add` 写进去的内容里，视频号卡片会失去 `video_snap_card` 属性**，
结果草稿箱里那个位置**一直显示「加载中」**，点不动、也播不了。

### 原因
视频号卡片不是一个普通 HTML 元素，而是微信编辑器里的一个**私有富组件**，
它的渲染依赖只能在编辑器前端生成的一段结构 + 会话态数据。
`draft/add` 接收的是静态 HTML 字符串，无法表达这个组件，于是被降级/丢弃。

### 本 skill 的做法
在正文里写：

```markdown
:::video 三分钟讲清楚 Remotion
这一期视频号里演示了从 Markdown 生成视频的完整流程。
:::
```

排版后，这一块会渲染成一张**占位卡**：上面写着「视频号」标签、视频标题、你的说明文字，
外加一行醒目的 `⚠️ 发布后请在公众号编辑器「视频号」里搜索并手动插入该视频（标题：…）`。

### 你的操作（约 10 秒）
1. 打开草稿箱里这篇文章 → 进入编辑器；
2. 找到那张占位卡；
3. 顶部工具栏点 **「视频号」** → 搜索视频标题/账号 → 选中该视频 → 插入；
4. 删掉占位卡。

## 3. 引用「其他公众号文章」（站内超链接）

### 现象
你想在文中说「详见我们上一篇《XXX》」并做成可点的蓝字。
如果直接在 Markdown 里写 `[《XXX》](https://mp.weixin.qq.com/s/xxxx)`，
脚本会把它当**外链**处理成脚注——因为从 API 侧看，任何 `<a href>` 都无法被识别为「站内文章选择器」。

### 原因
微信的「文章超链接」同样是**编辑器私有组件**（背后是一个 `appmsg` 类型的元素），
官方 FAQ 明确：**插入其它公众号文章链接，请在编辑器工具栏用「超链接 → 选择其它文章」**，
而不是给一段 URL。API 侧没有对应字段。

### 本 skill 的做法
```markdown
:::article 官方团队的排版指南
https://mp.weixin.qq.com/s/xxxxxx
为什么推荐：把移动端字号、行高、留白的经验讲透了。
:::
```

渲染成「关联阅读」占位卡：含标题、URL（纯文本，**不会**被转成脚注）、说明、以及 `⚠️` 提示。

### 你的操作
1. 进入编辑器，找到「关联阅读」占位卡；
2. 选中卡里的标题文字；
3. 工具栏点 **「超链接」→「选择其它文章」** → 搜到目标文章 → 确定（变成蓝字可点）；
4. 删掉 URL 行与提示行。

> 想让整块看起来像个「卡片」而不是行内蓝字？可以用编辑器的「引用」或把你自己的往期文章
> 做成一张带封面的**图文卡**——这属于编辑器里的手动美化，skill 不代劳。

## 4. 往期推荐 / 合集

同理，是编辑器组件。用法：

```markdown
:::readmore 往期推荐
- 用 Markdown 写公众号 | https://mp.weixin.qq.com/s/aaa111
- 免费生图 API 实测 https://mp.weixin.qq.com/s/bbb222
:::
```

每条渲染一行「标题 + URL」，整体套一张「往期推荐」占位卡。
发布后在编辑器里逐条用「超链接」替换；若你有**合集**功能，也可以整块换成合集卡片。

## 5. 其它富组件（都建议手动插）

下面这些在编辑器工具栏里都有，但都过不了 API，统一「手动插」：

| 组件 | 编辑器入口 | 备注 |
|------|-----------|------|
| 上传的视频 | 「视频」 | 腾讯视频链接同理 |
| 音频 / 语音 | 「音频」 | 需要在后台先有音频素材 |
| 小程序卡片 | 「小程序」 | 需要关联的小程序 AppID |
| 位置 | 「地理位置」 | |
| 名片（别的公众号） | 「公众号名片」 | |
| 投票 | 「投票」 | 发布后不可改选项 |
| 表格转图片 | 第三方工具 | 微信表格渲染不稳，长表格建议转图 |

**通用套话**：API 只能表达标准 HTML；凡是在编辑器里以「弹窗选择器」方式插入的、背后带微信私有
数据的东西，API 都表达不了。这不是本 skill 的能力缺口，是微信的接口边界。

---

## 6. 外链为什么会被「转脚注」

正文里写 `[官方文档](https://docs.example.com)`，微信会**过滤掉**这个 `<a>`（外部域名不允许直接跳）。
本 skill 在排版阶段就把它转成：

```
官方文档 [1]      ← 正文中，上标
……
参考链接
[1] 官方文档: https://docs.example.com    ← 文末
```

所以**外链不用你操心**，正常写 Markdown 就行。需要读者「点一下就能跳」的场景，
请改用 §3 的站内文章链接，或放到「阅读原文」（frontmatter `source_url`）。

## 7. 推荐工作流

```
写 article.md（正文里用 :::video / :::article / :::readmore 标好占位）
        ↓  python scripts/publish.py article article.md --cover images/cover.jpg
草稿箱出现成品（文字/图片已就位，占位卡还在）
        ↓  在公众号编辑器里：替换占位卡 → 插入视频号 / 站内链接
手动点「发布」
```

占位卡是**故意设计成显眼**的：它是你进入编辑器后的「待办清单」。
每替换掉一张，就删掉那张卡，最后不会有任何提示残留。

> 如果某篇文章不需要这些组件，不写这三个容器即可，正文里不会有任何占位痕迹。
